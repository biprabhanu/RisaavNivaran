# PlumeProof evaluation

> Generated by `python -m plumeproof.scenarios` at 2026-11-20T20:50:49+00:00, seed 2026, 25 scenarios. **All scenarios are simulated.** Re-run it from the Evaluation page ("Re-run evaluation") or with `POST /api/evaluate`. These numbers come from running the code; none were typed in by hand.

## Method

- 25 seeded scenarios, each with a hidden true emission source (waste surface / gas collection / flare) and a true pre-intervention emission E0 ∈ [600, 3500] kg/h.
- Scenario tags: ambiguous (flat prior 0.36/0.34/0.30, uniformly drawn true source), missing records (records request gets no response before the 7-day deadline), inspector unavailable (OGI inspector), conflicting measurements (first verification campaign returns two non-overlapping readings), unsupported claim (the operator's first repair claim is false), recurrence (emission returns 300 days after closure). Untagged scenarios are plain.
- The world answers each investigation by sampling y ~ P(y | true source, action) from the likelihood tables in `config.py`. Answers and measurement noise are pre-sampled per scenario, so all policies face the same world.
- The operator repairs whatever source it is told (A: its own guess) and always files a repair claim. The repair is effective (E → 0.25·E0) only if it targets the true source and the claim is not an unsupported one.
- Independent measurements report truth ± bounded noise (|error| ≤ 0.8·u, u = 0.15·truth + 50 kg/h). The pre-intervention satellite estimate is E0 ± 25%.

## Policies

- **A: Alert-only**: Sends one automated alert to the national focal point; no investigation; marks the case resolved as soon as the operator claims a repair.
- **B: Fixed checklist**: Runs the same sequence for every case (records → OGI → ground survey), attributes to the most probable source, notifies, and closes on the operator's repair claim after a checklist sign-off.
- **C: PlumeProof**: Ranks investigations by EIG/(cost+λ·time), stops when one source reaches 60%, gets human approvals, rejects claim-only closure, requires an independent measurement, re-plans after failed repairs, and reopens on recurrence.
- **C-ablation: planner disabled**: Identical to C but the Evidence Planner is replaced by 'cheapest available action first'.

## Metric definitions

- **false_closure**: Case closed AND (no independent VERIFIED_REDUCTION verdict behind the closure OR the hidden true emission was not actually reduced, i.e. true post ≥ 0.5·E0). Target: 0.
- **closed**: The case reached a closed/resolved state at some point (a later automatic reopen does not undo the count; see final_status = RECURRING).
- **resolved**: The operator's repair actually hit the hidden true source and was effective (true emission reduced), regardless of the paperwork.
- **inspections**: Field inspections: OGI surveys, ground surveys and independent measurement campaigns (actions with is_field_inspection). Records requests and satellite waits are not inspections.
- **inspections_per_resolved**: Total inspections / resolved cases.
- **attribution_inspections_per_case**: Field inspections used to IDENTIFY THE SOURCE (OGI + ground surveys; excludes verification campaigns), mean per case. PDF objective 2.
- **cost_per_resolved_inr**: Total investigation + verification cost (₹) / resolved cases.
- **days_to_stakeholder**: Simulated days from detection until the accountable operator is formally identified and assigned (A: alert forwarded by the national focal point; B: manual lookup; C: overlay + approval).
- **traceability_pct**: % of critical decisions (investigation, attribution, notification, closure) that link the evidence their kind requires (investigation→observation, attribution→finding, notification→attribution decision, closure→independent VERIFIED_REDUCTION verdict) AND have a recorded human approval.
- **correct_attribution_rate**: Share of all cases where the policy's final attributed source equals the hidden true source (A never attributes → 0).
- **mean_days_to_closure**: Mean simulated day of closure, over cases that were closed.

## Ablation: planner disabled

With the Evidence Planner replaced by "cheapest action first", PlumeProof keeps its verification gate (0 false closures), but it spends 78.8 days to closure on average vs 46.7 for C. Its correct-attribution rate is 100% vs 100%, and it needs 3.24 vs 3.00 inspections and ₹127,400 vs ₹128,000 per resolved case. Cheapest-first starts with the free satellite wait (30 days, 0 bits about the source).

## PlumeProof vs fixed checklist

C needs 3.00 inspections per resolved case vs 3.00 for B, and ₹128,000 vs ₹136,667. C's count *includes* its independent verification campaigns, which B never pays for. Counting only the inspections used to identify the source, C needs 0.72 per case vs 1.80 for B. False closures: C 0, B 25.

## Sensitivity (±20% likelihoods)

- Ranking stability: in 200 draws, every P(y|h,a) is multiplied by U[0.8, 1.2] and renormalised. The top-ranked action is unchanged in **100.0%** of draws. Mean Kendall τ vs the nominal ranking: **0.955**. Top-action counts: records_request 200.
- Robustness: C is run on worlds whose *true* likelihoods are perturbed ±20% while the agent keeps the nominal tables. False closures: **0**. Inspections per resolved case: 2.36.

## Notes and honest limitations

- All 25 scenarios, operator behaviour, inspector availability, records content and measurements are SIMULATED. Likelihoods, costs and delays are illustrative demonstration values (docs/ASSUMPTIONS.md).
- Fairness: each scenario's world answers and measurement noise are pre-sampled once, so every policy faces the same world.
- Recurrence scenarios: 5. Automatically reopened after closure: A: Alert-only 0, B: Fixed checklist 0, C: PlumeProof 5, C-ablation: planner disabled 5. A and B do no post-closure monitoring.
- Field inspections used for SOURCE ATTRIBUTION only (excluding verification campaigns), mean per case: A: Alert-only 0.00, B: Fixed checklist 1.80, C: PlumeProof 0.72, C-ablation: planner disabled 0.84. PlumeProof's totals above also include its independent verification campaigns, which A and B never pay for.
- A and B close on the operator's repair claim, so every closure they make is a false closure by definition (no independent evidence). This follows from their design; it is not a tuned result.
- Measurement noise is bounded (|error| ≤ 0.8·u). With unbounded (e.g. Gaussian) noise, rare false verified reductions become possible for any policy that relies on measurements.
- Policy behaviours for A and B are our models of an alert-only system and a fixed checklist. They are not measurements of any real system.
- Delays (approval 1 day, alert forwarding 30 days, manual stakeholder lookup 7 days, repair 14 days) are assumptions.
- The expert-assessment metric from the proposal (environmental-engineer review of priorities) is not yet done.
